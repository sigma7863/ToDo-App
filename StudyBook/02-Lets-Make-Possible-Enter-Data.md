今回はデータを定義する実装をしただけなので、まだ動作に変化はありません。ただ、上記のコードには今まで解説していない要素がいくつか含まれているので順番に解説します。

まず todo という変数を宣言しています。この todo にはフォームへ入力した文字列を保存する予定です。その後の remember{} は「この Composable が更新されても {} 内のデータは保持する」という働きをします。Jetpack Compose は状態に合わせて見た目を変更する 宣言的 UI という仕組みになっているため、Composable は頻繁に更新されます。Composable が更新されてもデータが消えないように remember{} を宣言しています。宣言的 UI についてはあとの講義で詳しく説明します。

そして remember{} の中に記載した mutableStateOf("") は状態（State）であることを宣言しています。mutable というのは変更可能という意味です。mutableStateOf() の引数には初期状態を渡すことができるので、今回は初期状態として空文字 "" を設定しています。初期状態に空文字を指定したので、Kotlin が型を推論してくれて、String 型の State になりました。todo にカーソルを合わせると、型が MutableState<String> になっていることがわかります。

型推論されている

Jetpack Compose では、上記で作成したような状態（State）をもとにして見た目が更新されます。この State を入力フォームに渡すことで、フォームに入力された文言を保存してそのまま表示できるようになるわけです。

とは言ってもイメージが掴みにくいと思いますので、まずは Jetpack Compose が見た目を作成・変更する宣言的 UI という仕組みについて解説しましょう。

【講義】宣言的 UI とは
宣言的 UI とは、対象となる状態（State）をもとにして UI を作成・変更・削除する仕組みです。複雑な見た目を表現する方法として宣言的 UI はとても有効であることがわかっており、以下のフレームワーク・ライブラリでも採用されています。

React（Web）
SwiftUI（iOS）
Flutter（クロスプラットフォーム）
宣言的 UI の仕組みやメリットを理解するには、宣言的 UI が生まれる前に一般的だった命令的 UI と比較するのが良いでしょう。それぞれの特徴は以下のようになります。

命令的 UI: ユーザが入力したら、その内容をもとに UI を作成・更新して、データも更新する
宣言的 UI: ユーザが入力したら、その内容をもとにデータを更新して、データに基づいて UI が自動的に作成・更新される
つまり、命令的 UI では開発者が全てのコードを書く（命令する）必要がありましたが、宣言的 UI ではデータの管理（宣言）を行えば十分であるということです。

具体的な例で見てみましょう。例えば今回のような入力フォームを作成する場合、命令的 UI では以下のような処理を実装します。

フォームに TODO が入力されたら、その TODO を保存する
保存された TODO を表示するための View を TODO 一覧に追加する
一方で宣言的 UI では、データを追加するだけです。

フォームに TODO が入力されたら、その TODO を保存する
保存された TODO が View に反映される
このような簡単な機能であれば、どちらの実装でも問題ないでしょう。しかし、機能が増えてくるにつれて命令的 UI だと実装が大変になってきます。例えば新しく TODO を削除する機能を追加する場合は、以下のような実装が追加で必要になります。

任意の TODO において「削除」が実行されたら、その TODO の View を削除する
削除された TODO をデータの中から探して削除する
一方で宣言的 UI では、データを削除するだけです。

任意の TODO において「削除」が実行されたら、その TODO のデータを削除する
削除された TODO のデータを表示していた View が削除される
この他にも「編集」や「並べ替え」や「順番入れ替え」などの機能を追加していくと、そのたびに命令的 UI では見た目とデータの処理を実装しなければならないのでどんどん複雑になっていきます。そのうちにどこかでデータと View の不整合が起きてしまい、編集しようとした TODO がすでに削除されていた、などの不具合も発生する可能性があります。

一方で宣言的 UI では、機能が増えてもデータを操作するだけなので負担が少ないです。データと View の不整合が起こることもありません。このように利点が大きいため、さまざまなプラットフォームで宣言的 UI を用いたライブラリが普及しているのです。

まとめると以下の通りです。

命令的 UI	宣言的 UI
UI の作成方法	それぞれの View を作成してデータを入れる	データを作成したら自動的に View が作成される
UI の変更方法	変更があった View を特定して、新しい View に差し替える	データを更新したら自動的に View が更新される
UI の削除方法	削除する View を特定して、その View を削除する	データを削除したら自動的に View が削除される
宣言的 UI のメリットを体感するため、入力フォームの実装に戻って実際にコードを書いていきましょう。

【実習】状態に応じて UI を変えよう
それでは先ほど作成したデータを入力フォームに反映させてみましょう。MyTodoApp() の入力フォームの実装部分を、以下のように実装してください。

Column {
    Text(text = "My TODO", fontSize = 32.sp)
    TextField(
        value = todo.value,
        onValueChange = { text -> todo.value = text },
        modifier = Modifier
            .padding(top = 24.dp, bottom = 16.dp)
    )

実装ができたらアプリをビルドして入力フォームに文字を入力してみましょう。今回は入力した文字が表示されるようになっているはずです。

フォームに入力できるようになった

入力フォームに文字が表示されるようになった理由を順番に説明していきます。

まず、onValueChange = { text -> todo.value = text } という部分で、フォームに入力された内容を todo.value へ保存するようにしました。onValueChange の型は (String) -> Unit となっていますので、入力された値が String 型のパラメータとして渡されます。そのため、text で入力された文言を受けとって、todo.value = text で todo に代入して保存しています。

onValueChange の型と説明

そして、value = todo.value という部分で、保存された todo.value をフォームの値に代入しています。つまり、フォームに文字が入力されると、1文字ごとに以下の処理が実行されています。

onValueChange に渡した処理が実行されて、フォームに入力された文言が todo.value に保存される
保存された todo.value がフォームに表示される
また、この処理は文字を削除したときにも同じように実行されます。エミュレータのキーボードで delete ボタンを押して文字を削除すると、フォームの文字も削除されるのがわかるでしょう。

これがまさに宣言的 UI の仕組みでもあります。入力フォームはあくまでも状態（State）を表示・変化させるものであり、状態に応じて見た目が変更されるということです。このようにして Jetpack Compose では UI の挙動を管理していきます。

TODO の一覧は複数のテキストを含むので、状態（State）は mutableStateListOf<String>() を使用します。Kotlin では配列を扱うときは主に List という型を使います。mutableStateListOf() というのは List という型で State を作成する処理です。

リストにはどんな型の値が入ってくるかを宣言する必要があるので、<String> として型をつけています。String 型のリストには Int や Boolean 型の値を入れることはできません。リストの値は全て String 型であることが保証されます。もしリストの中に Int や Boolean も入れたい場合は、Any 型のリストにすれば良いですが、型が特定できなくなってしまうのでなるべく避けたほうが良いです。

さて、TODO 一覧を保存するデータが定義できたら、次は「追加」ボタンを押したときにフォームの文言を保存してみましょう。Button の onClick に以下の処理を実装してください。

// onClick に処理を追加
  Button(onClick = { todoList.add(todo.value) }) {
    Text(text = "追加")
}

onClick はボタンがタップされたときに実行する処理を渡す引数です。上記のように実装することで、「追加」ボタンをタップしたらフォームに入力された文言が todoList に保存されます。add() は名前の通りリストに値を追加する処理で、引数に追加したい値を入れます。

todoList に値が入ったので、todoList に入っている値を一覧で表示してみましょう。Button の下に todoList を forEach() という処理を使って以下のように実装してください。

Button(onClick = { todoList.add(todo.value) }) {
    Text(text = "追加")
}
 todoList.forEach { item ->
    Text(text = item)
 }

実装できたらアプリを起動して、フォームに入力して「追加」ボタンを押してみましょう。ボタンの下に入力した内容が表示されていれば OK です。

TODO の一覧が表示された

追加した forEach というのは List の要素ごとに処理を実行する関数です。JavaScript の配列の要素ごとに処理を実行する forEach という関数と同じような動作をします。ここでは List の要素を item として受け取って、Text の文言として代入しています。

これでフォームに入力して、一覧として表示するという処理が実装できました。各要素を並べただけなので見た目は整っていないですが、これは後の学習で整えるので今はこのままにしておきましょう。

ただ、今の実装だと「追加」ボタンを押してもフォームに入力した値が残ってしまっているので、続けて入力がしづらいですね。「追加」ボタンを押したらフォームの中身をリセットするために、Button の onClick の中の修正を変更しましょう。

 Button(onClick = {
    todoList.add(todo.value)
    todo.value = ""
 }) {
   Text(text = "追加")
}

Button の onClick の中で、todo.value を空文字にする処理も実行するようにしました。アプリをビルドして、「追加」ボタンを押したときにフォームの中身がリセットされることを確認しましょう。
